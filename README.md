# Ulefone Armor Pad 5 Ultra — Android + Linux

## Цель проекта

Исследовать и реализовать технически обоснованный способ совместного использования Android и Linux. Цели и границы утверждены в [Project Charter v0.1](docs/project-charter.md).

## Текущий статус и идентификация устройства

Начальный сбор информации. Точная модель конкретного экземпляра, аппаратная ревизия, платформа и кодовое имя пока не подтверждены. Название проекта Ulefone Armor Pad 5 Ultra задаёт объект исследования, а не результат идентификации. Ранее в исходном описании владельца использовалось название Ulefone Armor 5 Ultra; расхождение сохраняется в [паспорте](docs/device.md).

Сборок ОС и проверенных инструкций по прошивке пока нет. Поддержка оборудования не заявлена.

## Приоритеты совместимости

Сначала исследуем аппаратную платформу. Основные функции устройства и встроенный проектор имеют приоритет; остальные компоненты исследуем и интегрируем постепенно. Зависимости проектора от заводской системы предстоит определить.

## Первая крупная техническая цель

Безопасная воспроизводимая сборка Android для исследуемой платформы по [критериям Charter](docs/project-charter.md#первая-крупная-цель-сборка-android). Успешная сборка, загрузка образа на планшете и проверка оборудования — отдельные результаты. Сборка не разрешает прошивку и не доказывает работу проектора.

## Открытая архитектура Android + Linux

Архитектура совместного использования не выбрана. Необходимо сравнить технически обоснованные варианты с учётом функций устройства, проектора, безопасности, ресурсов и сопровождения. Ни dual boot, ни виртуализация, ни контейнеры, ни нативный Linux заранее не объявлены совместимыми.

## Первые шаги

- [ ] Подтвердить модель и аппаратную ревизию, заполнить паспорт с источниками и статусами.
- [ ] Зафиксировать заводскую ОС, сборку, платформу и ядро.
- [ ] Найти официальный источник заводской прошивки, изучить загрузчик и восстановление.
- [ ] Исследовать встроенный проектор и его программные зависимости.
- [ ] Найти применимые исходники ядра, конфигурации, сборочную базу и проверить лицензии.
- [ ] Подготовить безопасную инфраструктуру и воспроизводимую сборку Android.
- [ ] Сравнить архитектуры Android + Linux без преждевременного выбора.

## Организация работы

GitHub хранит версии проекта; Codex используется для инженерной работы; `aosp-build` предназначен для сборок и аппаратных испытаний. Эти роли не подтверждают готовность сервера и не дают разрешения на подключение или команды на планшете.

В `main` храним проверенную документацию и принятые изменения. Для задач используем короткие ветки, например `research/device-info`, `research/kernel-sources`, `android/bringup`, `linux/bringup`. Изменения возвращаем через PR с результатом и проверками; любые операции Git выполняются в пределах задания.

## Безопасность и чувствительные данные

Опасные операции требуют оценки риска и отдельного разрешения по [safety](docs/safety.md). До подтверждения модели и возможности восстановления не выполняйте разблокировку, очистку или запись разделов по случайным инструкциям. Разблокировка может удалить пользовательские данные. Наличие инструкции не означает разрешения.

Дампы, резервные копии и логи проверяйте на IMEI, серийные номера, ключи, аккаунты и другие личные данные. Крупные образы и результаты сборки не храним в Git; для разрешённых к распространению файлов фиксируем источник, версию и контрольную сумму.

## Лицензирование

Лицензия проекта пока не выбрана. Перед добавлением стороннего кода, прошивок или бинарных компонентов необходимо проверить права распространения и сохранить их лицензии. Публичность репозитория сама по себе не предоставляет лицензию на его содержимое.
